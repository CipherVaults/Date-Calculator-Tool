## 0. Key design decisions (read first)

1. **Dates are integer civil days.** Both engines (Rust `date-core` and the mobile inline JS) work only on proleptic-Gregorian `(y, m, d)` and on `i64` day numbers (epoch 1970-01-01 = 0, Hinnant `days_from_civil` / `civil_from_days`). The JS engine slice must never use `Date`, `Intl` or `toISOString`. CI enforces this with a static regex. This makes the engine independent of timezone and DST and lets it match Rust byte for byte.
2. **Supported range is 0001-01-01..=9999-12-31.** Inputs pass through as strict ISO `YYYY-MM-DD` strings. A result outside the range returns an error result and never panics.
3. **"Now" and "today" are always inputs to the core.** The UI computes them from local `new Date()` components (`getFullYear/getMonth/getDate/getHours…`, never `toISOString()`, which is UTC). The core stays pure and deterministic.
4. **Result shape keeps the reference convention.** Results use `#[serde(tag = "ok")]` with `"true"`/`"false"` string tags, as the reference CI expects (`act.ok === "true"`). The core also produces the display strings (`label`, `liveResult`, `traceLines[]`, `copyText`), so display text is covered by parity too.
5. **The calendar comes from settings, not from UI arguments.** Business-day commands read the weekend and holiday configuration from `SettingsState`, so the UI and backend cannot drift. Core functions take an explicit `&CalendarConfig`, which lets the bridge and golden tests pass it in.
6. **IPC input validation lives in the core.** Put it in `date_core::api` (string → validated request) so `src-tauri/commands.rs` and `examples/eval_bridge.rs` share one implementation. The reference duplicated these rules in the bridge; this is a small improvement.
7. **Golden fixtures are generated by Rust** (`examples/gen_golden.rs`, seeded PRNG). Rust is the source of truth here, and there is no legacy JS oracle. Independent correctness comes from a chrono dev-dependency oracle, published holiday tables and the separate JS oracle in safety-eval.

### crates/date-core
- **Cargo.toml**: `name="date-core" version="1.0.0" edition="2021"`, with authors and description adapted. `[dependencies] serde={version="1",features=["derive"]}`. `[dev-dependencies] serde_json="1"` and `chrono={version="0.4",default-features=false,features=["std"]}` (oracle only, never at runtime). Add `[[example]]` entries only if needed; auto-discovery works.
- **lib.rs**: `pub mod` declarations, plus re-exports of `calculate_between`, `calculate_add_subtract`, `calculate_business_days`, `calculate_age`, `calculate_date_info`, `calculate_countdown`, `holidays_for_year`, `month_grid`, `CalendarConfig`, `WeekendMask` and the result enums. Also `pub const MIN_DAY`, `MAX_DAY` and `ENGINE_VERSION: &str = "1.0.0"`.
- **civil.rs**: Hinnant algorithms using `div_euclid`/`rem_euclid` everywhere (JS mirror: an explicit `floorDiv`/`mod` helper; JS `%` truncates). ISO weekday 1=Mon..7=Sun. `iso_week(y,m,d) -> (iso_year, week)`. `add_months_clamped(y,m,d,delta_months)` clamps to the month's last day, matching chrono `checked_add_months`.
- **parse.rs**: `parse_iso_date(&str) -> Result<Civil, &'static str>`. It accepts exactly `^\d{4}-\d{2}-\d{2}$`, ASCII only (no fullwidth digits, signs, whitespace or 5+ digit years), with a valid month/day and a year from 1 to 9999. `parse_hhmm` accepts `""` (meaning 00:00) or `^\d{2}:\d{2}$` with h<24 and m<60. `parse_whole(&str, max)` accepts `^\d{1,7}$` and ≤ max; empty means 0.
- **format.rs**: `group_thousands(i64)` → `"1,234,567"` (ASCII comma, fixed, no locale). `plural(n,"year")`. Weekday names Monday..Sunday and their 3-letter forms. Month names. `iso(c)`.
- **between.rs** (mode 1). Algorithm: if end < start, swap and set `reversed=true`. If includeEnd, end += 1 day. Total months = the largest k such that `add_months_clamped(start,k) <= end`, always anchored on the original start, not iteratively. years = k/12, months = k%12, days = end − anchor. Totals: totalDays, weeks + remainder days, hours = d×24, minutes, seconds (i64; ≤ 3.16e11 fits JS safely). Outputs: `label` ("1 year, 1 month, 15 days" or "Same day"), `liveResult`, `traceLines` (see §6), `copyText`. Errors: invalid dates. With includeEnd and end=9999-12-31, compute in day numbers, not civil dates, so it cannot overflow.
- **add.rs** (mode 2). Inputs: start, op add|subtract, years, months, weeks, days, business: bool. Calendar mode: apply `±(12y+m)` months clamped once, then `±(7w+d)` days, and record a `clampedFrom` note when the day was clamped. Business mode: years/months/weeks must be 0 (the UI hides them); step one day at a time in the chosen direction, counting only business days, until `days` is reached. n=0 returns start with the note "start is not a business day" when that applies. Cap business n ≤ 100,000. Range errors: "Result is outside the supported range (0001-01-01 to 9999-12-31)".
- **business.rs** (mode 3). Count over `[start,end]` if includeEnd, else `[start,end)`, with the start always included (timeanddate semantics). Use week arithmetic: full weeks × business days per week plus a remainder scan, then subtract the deduplicated holiday dates that fall on business days in the range (one `holidays_for_year` call per year covered). Outputs: calendarDays, businessDays, weekendDays, holidayWeekdays, `holidaysHit` (first 20 `{date,name}` plus a `moreCount`), plus label/trace/copy.
- **age.rs** (mode 4). Uses the same y/m/d engine as between (birth→asOf, includeEnd=false). Also totals in months, weeks and days. Next birthday: Feb-29 birthdays fall on Feb 28 in common years (consistent with clamping; documented as an open decision). Outputs nextBirthday ISO + weekday, daysUntil, ageAtNext, and an `isBirthdayToday` flag. Error "Birth date is after the as-of date".
- **info.rs** (mode 5). Inputs: date and today. Outputs weekday, isoYear/isoWeek ("2026-W47-1"), dayOfYear/daysInYear, quarter, isLeap, daysLeftInYear (days after the date through Dec 31), daysLeftInMonth, relative ("in 12 days" / "3 days ago" / "today"), businessDay yes/no, and the holiday name if any, using the CalendarConfig.
- **countdown.rs** (mode 6). Inputs: targetDate, targetTime (HH:MM or empty), nowDate, nowSecondsOfDay. Delta = civil seconds, ignoring DST (documented). Outputs past flag, totalSeconds, d/h/m/s, `label` "46d 14h 03m 22s" or "elapsed 2d 01h 00m 00s", and businessDaysLeft (from nowDate to targetDate exclusive) when not past.
- **calendar.rs**:
  - `WeekendMask(u8)`, bit0=Mon..bit6=Sun. Presets satSun, friSat, friOnly, custom. Validation rejects 0x7F with "Weekend cannot cover all seven days". An empty weekend is allowed.
  - `CalendarConfig { weekend, preset: None|Us|Uk|Eg, islamic_offset_days: i8 (-3..=3), disabled_holidays: Vec<String> (allowlisted ids, ≤64), custom_holidays: Vec<CustomHoliday> (≤200), overrides: Vec<HolidayOverride> (≤100) }`.
  - `CustomHoliday { name (trimmed, 1..=64 chars, no control chars), month 1..=12, day 1..=31 valid for month (Feb 29 allowed and applied only in leap years), year: Option<i32> (None = yearly) }`.
  - `HolidayOverride { id, year, date }` sets the actual announced date of an approximate holiday (for example Eid) for one year.
  - `validate_calendar(&CalendarConfig) -> Result<(), &'static str>`.
- **holidays/**:
  - `rules.rs`: Fixed, NthWeekday, LastWeekday, Easter±k, OrthodoxEaster±k, Hijri(month,day,span) and one-off table. Each rule has a `since` year. Rules apply for 1900..=2199 (outside that range the list is empty and the UI notes it); custom holidays apply to any year.
  - `easter.rs`: Western = Anonymous Gregorian (Meeus/Jones/Butcher). Orthodox = Meeus Julian algorithm → Julian date → JDN → Gregorian. Convert exactly; do not use the +13 shortcut.
  - `hijri.rs`: tabular Islamic calendar, civil epoch, leap rule `(14+11y) mod 30 < 11`, integer-only: `jdn = d + (59(m−1)+1)/2 + 354(y−1) + floor((3+11y)/30) + 1948439`. Both the Hijri→JDN and JDN→Hijri directions are needed to find the 1–2 Hijri years that overlap a Gregorian year. Apply islamic_offset_days, then overrides.
  - `us.rs`: New Year, MLK (3rd Mon Jan, since 1986), Washington's Birthday (3rd Mon Feb), Memorial (last Mon May), Juneteenth (Jun 19, since 2021), Independence, Labor (1st Mon Sep), Columbus (2nd Mon Oct), Veterans (Nov 11), Thanksgiving (4th Thu Nov), Christmas, all since 1971 unless noted. Observed: Sat→Fri, Sun→Mon. Jan 1 on a Saturday gives Dec 31 of the previous year, so `holidays_for_year(Y)` must also evaluate rule-year Y+1.
  - `uk.rs` (England & Wales): New Year, Good Friday, Easter Monday, Early May (1st Mon May, since 1978), Spring (last Mon May), Summer (last Mon Aug), Christmas, Boxing Day. Substitution: a holiday on Sat/Sun moves to the next Mon–Fri not already taken, processed in date order; this yields Dec 27/28 correctly. One-off table: 1995-05-08 (Early May moved), 1999-12-31, 2002-06-03/04, 2011-04-29, 2012-06-04/05, 2020-05-08 (Early May moved), 2022-06-02/03, 2022-09-19, 2023-05-08.
  - `eg.rs`: Coptic Christmas Jan 7, Jan 25 Revolution/Police Day, Sinai Apr 25, Labour May 1, Jun 30 (since 2014), Jul 23, Oct 6 Armed Forces, Coptic Easter (Orthodox Easter Sunday), Sham El-Nessim (Orthodox Easter Monday), Islamic New Year (1 Muharram), Mawlid (12 Rabi I), Eid al-Fitr (1–3 Shawwal), Arafat (9 Dhu al-Hijjah) and Eid al-Adha (10–12 Dhu al-Hijjah). Hijri-based items carry `approx: true`. No substitution rule; Egypt's decree-based moves to Thursday are handled by overrides or custom holidays.
  - Stable ids, an allowlist exported as `HOLIDAY_IDS`: `us.new_year … us.christmas`, `uk.*`, `eg.*`, plus `uk.special`.
  - Output: `Holiday { id, name, date (effective/observed ISO), actualDate, observed: bool, approx: bool, source: preset|custom|override }`, deduplicated by date for counting but listed separately.
- **grid.rs**: `month_grid(y, m, first_day_of_week, cal, highlight: Option<(start,end)>, today) -> Vec<Cell>`, 42 cells `{iso, day, inMonth, weekend, holiday (name or null), inRange, isStart, isEnd, isToday}`.
- **api.rs**: request structs taking `String`/`bool`/`Option<String>`. `pub fn ipc_between(req) -> BetweenResult` and so on. Invalid strings become the error variant, never an `Err` across IPC. `validate_calendar` is exposed here too, so the bridge's "ipc" surface equals the Tauri behaviour.

## 5. History entry shape (500 entries, 1 MiB file, newest first, consecutive-duplicate coalescing)

```rust
#[serde(deny_unknown_fields, rename_all = "camelCase")]
pub struct HistoryEntry {
  id: u64, timestamp_ms: u64,
  calculator: String,          // between|add|business|age|info|countdown (allowlist)
  calculator_label: String,
  inputs: HistoryInputs,       // typed, all Option<String>, deny_unknown_fields
  inputs_text: String, result_text: String, copy_text: String,
}
pub struct HistoryInputs { start, end, include_end, op, years, months, weeks, days, business,
                           birth, as_of, date, target, time }   // each Option<String>, skip_serializing_if none
```

Per-calculator required and allowed keys. All others must be `None`, otherwise the error is "unexpected input for calculator".

| calculator | keys |
|---|---|
| between | start, end, includeEnd("true"/"false") |
| add | start, op(add/subtract), years, months, weeks, days (digit strings ≤7), business(bool string) |
| business | start, end, includeEnd |
| age | birth, asOf |
| info | date |
| countdown | target, time (`""` or HH:MM) |

Rules: dates are validated with `date_core::parse::parse_iso_date`. The text fields keep the reference rules (non-empty, ≤256, no control characters, copyText may contain `\n`). Business entries put the calendar summary into `inputsText` (for example "2026-01-01 → 2026-01-31 · Sat/Sun · US federal"). Restore puts back the inputs only and recomputes with the current settings; a toast-free note goes in the result line. Dedup compares calculator + inputs + resultText. ## 7. Native date input strategy

- Use `<input type="date" min="0001-01-01" max="9999-12-31">` on both platforms, with `type="time" step="60"` for the countdown. Read **only** `.value` (an ISO string or `""`); never `valueAsDate` or `valueAsNumber` (UTC/epoch). The core parser is the single source of truth. If a very old browser falls back to `type=text`, the same strict ISO parser applies and the placeholder reads `YYYY-MM-DD`.
- **Desktop WebView2 (Chromium):** segmented keyboard entry in the system locale order, plus a picker icon, styled through `color-scheme: dark`. `input` fires with `""` while segments are incomplete, and the live panel shows "—". Enter triggers calculate (reference `attachEnterKey`). Year segments accept up to 6 digits, which the core rejects as out of range.
- **iOS Safari:**
  - An empty date input collapses and shows no placeholder. Set `-webkit-appearance:none; display:block; min-height:44px; font-size:16px` (avoids the zoom), `::-webkit-date-and-time-value{text-align:left}`, and an empty-state hint via a `.date-empty` class toggled in JS (class toggles only, no `.style`).
  - iOS cannot clear a value without the picker's Reset, so the card `clear` button is the clear path.
  - min/max are not enforced by the wheel; the core enforces them.
- **Android Chrome:** a native dialog with Clear. No special handling.
- The **today** buttons (`.today-btn`, text "today") fill the value from local `todayParts()`. **Swap** appears on modes 1 and 3. Integer fields use `type=number inputmode=numeric min=0 step=1` plus the adapted paste sanitizer (digits only, ≤7).

## 8. Icons (no external downloads)

`scripts/generate-icons.mjs` is zero-dependency Node and runs `node scripts/generate-icons.mjs`:
- It builds RGBA buffers with its own rasteriser (filled and stroked rectangles plus circles at 4× supersampling, box-filter downsampled). It encodes PNGs by hand: signature, IHDR, IDAT via `zlib.deflateSync(level 9)`, a CRC32 table, IEND.
- Glyph: #0E0F12 background; a square-cornered calendar body with a 2 px-equivalent #E9A715 outline and a solid gold header bar; two ring tabs; a 4×3 grid of day cells in #2a2d35 with one cell filled #94C59A; optionally a "31"-style mark drawn from rectangles (a 7-segment style, so no font is needed).
- Outputs:
  - `mobile/icons/icon-192.png` and `icon-512.png` (glyph at about 80%);
  - `icon-maskable-512.png` (full-bleed background, glyph inside the 80% safe zone, about 60%);
  - `apple-touch-icon.png` (180, opaque);
  - `assets/icon-source-1024.png`, `assets/icon.png` (256);
  - a printed base64 of a 64 px PNG for the mobile `<link rel=icon>` data URI.

- Output is deterministic for a given Node/zlib version. Commit the PNGs. CI only checks that they exist and are non-empty (manifest check), not that they regenerate identically.
- The icons must exist before the first `cargo build` of src-tauri: `tauri_build` embeds `icons/icon.ico` on Windows.

## 9. Golden fixtures and oracles

**Format** (`tests/fixtures/golden.json`, LF, one case per line for reviewable diffs):
```json
{"version":1,"generator":"gen_golden 1.0.0","seed":"0xDA7E2026","count":N,"cases":[
{"f":"between","a":{"start":"2024-01-31","end":"2025-03-15","includeEnd":false},"r":{...exact serde output...}},
...]}
```
The `a` arguments use the **IPC string surface** (`api.rs`), so invalid strings are covered too. An optional `cal` object carries the CalendarConfig.

**Case mix (target 12–15k cases, about 3–5 MB):**
- `parseDate` ×600: valid edges, `2023-02-29`, `2024-02-29`, `0000-01-01`, `10000-01-01`, `2024-1-05`, padded/whitespace, fullwidth digits, `+002024-01-01`, `""`.
- `between` ×2,500: month-end pairs, Feb 29, reversed, same day, includeEnd, 0001/9999 boundaries, random.
- `addSubtract` ×2,500: clamping (Jan 31 + 1m; Feb 29 + 12m), subtract, overflow errors, business mode with each preset and weekend.
- `businessDays` ×2,500: all 4 weekend presets plus random custom masks, all 4 presets, Islamic offsets, overrides, custom holidays, long spans of 50+ years.
- `age` ×800 (Feb 29 births).
- `dateInfo` ×1,200 (ISO-week boundary days: Dec 28–Jan 4 for every year type).
- `countdown` ×800 (past, future, time "", 23:59).
- `holidaysForYear`: every preset × years 1899, 1900–2199 step 1 for US/UK (needed for observed edge cases), Egypt with offsets −1/0/+1 for a sample of years, plus custom and override combinations.
- `monthGrid` ×400 (first-day variants).
- `validateCalendar` ×300 (adversarial: all-7 weekend, unknown ids, `__proto__` ids, 65-char names, control characters, Feb 30 custom, 201 customs).

**Regeneration discipline:** `gen_golden --check` runs in CI. A fixture change requires a ledger entry in Documentation/pbs explaining the behaviour change. AGENTS.md states that the fixture must never be regenerated just to make a parity failure pass; first decide which side is wrong, using the chrono oracle and the tables.

**Three-way assurance:**
1. Rust versus chrono and the published tables: independent correctness.
2. Rust versus golden: regression lock.
3. Mobile JS versus golden (CI node checks), plus Rust bridge versus mobile JS on fresh seeded inputs (safety-eval Slice B): parity on and off the fixture.

## 15. Build and verify commands (Windows)

Run Cargo from **PowerShell or Windows Terminal, never Git Bash**. Git Bash `/usr/bin/link` shadows MSVC `link.exe` and fails with "link: extra operand". In Claude Code, use the PowerShell tool for cargo and tauri; Bash is fine for node and gh. Check with `where.exe link`: the first hit must be under `...\MSVC\...\bin\Hostx64\x64`.

```powershell
git init; git config core.autocrlf false          # before the first add (CSP hashes are byte-exact)
node scripts/generate-icons.mjs
cargo install tauri-cli --version "=2.12.4" --locked
cargo tauri icon assets/icon-source-1024.png -o src-tauri/icons
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo run -p date-core --example gen_golden --locked -- --check   # (--write only for an intentional change)
node scripts/safety-eval.mjs --json target/safety-eval-system-card.json
cargo tauri dev
cargo run -p date-calculator-tool --locked -- --smoke-test        # debug = console subsystem, prints SMOKE_TEST_OK
cargo tauri build -- --locked
$p = Start-Process .\target\release\date-calculator-tool.exe -ArgumentList '--smoke-test' -Wait -PassThru; $p.ExitCode
node scripts/serve-mobile.mjs     # http://127.0.0.1:8787/Date-Calculator-Tool/
```

The CSP hash printer is the HANDOFF §9.C.6 here-string adapted: piping a single-quoted here-string into `node` works in PowerShell 5.1 and 7. Before the first `--locked` run, the lock must exist: run `cargo generate-lockfile` (or the seeded copy plus `cargo build` once without `--locked`), then commit it.

## Open risks
- Reference CI smoke step runs a GUI-subsystem release exe directly in PowerShell; it may not wait or propagate the exit code, so the reference smoke gate may be non-gating. The plan uses Start-Process -Wait -PassThru; verify in the first Windows CI run.
- The build.yml release job auto-publishes vX on the first green push to main. All work must go through a branch/PR until v1.0.0 is truly ready, and release-notes-v1.0.0.md must exist before merge.
- Creating CipherVaults/Date-Calculator-Tool (and making it public for free GitHub Pages) is an external action that needs explicit owner approval. The repo does not exist yet.
- Islamic holidays come from the tabular calendar and can be off by 1-2 days from Egyptian announcements. Egypt also moves holidays by decree (for example to Thursday). The plan covers this with an offset setting, per-year overrides and custom holidays, but results are labelled approximate.
- Owner decisions are still open: default holiday preset/weekend (plan: none + Sat/Sun), Feb-29 birthday rule in common years (plan: Feb 28; UK law uses Mar 1), credits/AI-builder list for About/footer/Cargo authors, and whether the business-day count includes the start date (plan: start included, end toggle).
- Countdown ignores DST (civil-seconds delta), so it can be off by 1 hour across a DST transition. This is documented as a limitation.
- Golden fixtures are Rust-generated, so Rust-vs-golden only proves regression. Correctness depends on the chrono oracle, the hand-entered published holiday tables (transcription errors possible) and the safety-eval independent JS oracle.
- Inlining the large engine in mobile/index.html makes every edit change the script SHA-256. The CSP hash must be recomputed after every change, and autocrlf must stay false or the hashes break.
- The inline node verification block is triplicated (build.yml, pages.yml, AGENTS.md here-string) to mirror the reference. Drift between the copies is a maintenance risk.
- Seeding Cargo.lock from the reference keeps tauri 2.12.5 compatible with tauri-cli =2.12.4. A fresh resolve could pull a newer tauri that mismatches the CLI, so keep the lock and --locked everywhere.
- Rewriting safety-eval.mjs (reference about 200 KB) is the largest single effort. The mini-DOM must gain type=date/time/checkbox semantics and a virtual clock, or Slice B/E results will be unreliable.
- Business-day counting over very long ranges (up to 9999 years) and business-day stepping (cap 100,000) must stay fast in mobile JS during live typing. Use week arithmetic, not per-day loops, for counts.
- Desktop WebView2 date input accepts 5-6 digit years and locale-ordered segments. The core rejects out-of-range years, but UX messaging must make this clear. iOS Safari empty date inputs need explicit CSS/empty-state handling.
